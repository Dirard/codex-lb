# Go v1.15.0 — форки ключей

## Изменения

- Владелец API-ключа может создавать дочерние ключи (форки) и управлять ими через API, используя свой ключ как Bearer: `GET`/`POST /v1/key/forks`, `GET`/`PATCH`/`DELETE /v1/key/forks/{id}`. Форк — настоящий ключ: секрет (`sk-clb-fork-…`) показывается один раз при создании.
- Форк никогда не шире родителя. Модели, уровни рассуждения, тариф, срок действия и лимит пула проверяются по текущим настройкам родителя при каждой записи; нарушение — `422 fork_exceeds_parent` с именем поля в `param`. Группа, аккаунты, источники моделей, класс трафика, маршрутизация HTTP-клиентов и разделы отчётов берутся у родителя. Форк работает, только пока родитель активен и не истёк. Лимиты бюджета родителя действуют и на запросы форка: расход форка учитывается в лимитах родителя, включая перерасчёт цен. Удаление родителя удаляет его форки. У форка не бывает своих форков; у ключа — не больше 100 форков.
- Если администратор сужает родителя так, что форк выходит за рамки по моделям, уровням рассуждения или тарифу, такой форк выключается в той же записи. Его настройки сохраняются: владелец сужает форк и включает его снова.
- Пул запросов родителя общий для родителя и всех его форков. Форку можно задать собственный лимит внутри пула. В ответах на запросы форка есть заголовок `x-ratelimit-fork-used-requests` — сколько запросов за последнюю минуту этот форк занимает в общем пуле, — а при собственном лимите ещё и `x-ratelimit-fork-limit-requests`.
- Форки хранят, кто их создал и изменил (`owner` или `admin`) и когда. Действия с форками пишутся в журнал только с идентификаторами ключей.
- В дашборде список ключей помечает форки родителем. Страница родителя показывает его форки, страница форка ссылается на родителя. Редактор форка скрывает унаследованные настройки; администратор может менять, выключать, перевыпускать и удалять форки по тем же правилам.

## Обновление

Схема SQLite 51: в `api_keys` добавлены столбцы связи с родителем и аудита. Миграция аддитивная: обновление из **Settings → Runtime updates** проходит без простоя. Секреты форков хешируются в отдельном домене, поэтому предыдущая версия форки не принимает. Во время обновления и после отката на go-v1.14.0 форки отклоняются, а не обслуживаются без лимитов родителя. Протоколы обновления и передачи не меняются.

## Проверки и ограничения

- Гейты прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `go test -race`, `govulncheck`, `openspec validate`, тесты дашборда, сборка и контрактные тесты на собранном бинарнике.
- Маршрутные тесты проверяют весь цикл через `/v1/key/forks`, каждое поле, которое шире родителя, обслуживание на аккаунтах родителя, списание с лимита родителя, выключенного родителя, общий пул с заголовками форка и действия администратора. 15 мутаций (без наследования, без лимитов родителя, без проверки, без выключения при сужении, без перерасчёта и бэкфилла, свой скоуп у форка, лимит форка, хеш секрета, права и каскад) ловятся тестами.
- Генерация видео требует, чтобы сам форк был в списке допущенных к видео ключей.
- Перевыпустить секрет форка через API ключа нельзя: удалите и создайте форк заново или перевыпустите его в дашборде.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
