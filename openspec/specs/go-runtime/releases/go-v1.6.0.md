# Go v1.6.0 — генерация картинок через подписки ChatGPT

## Изменения

- Вернулись маршруты генерации и редактирования картинок, убранные при переходе на Go:
  - `POST /backend-api/codex/images/generations` и `/backend-api/codex/images/edits` — их вызывает встроенный в Codex `$imagegen`;
  - `POST /v1/images/generations` и `/v1/images/edits` — для клиентов OpenAI Images API. На `/v1/images/edits` принимается и multipart (`image`, `image[]`, `mask`), он превращается в JSON с data URL.
- Запрос уходит без изменений в images-эндпоинт ChatGPT Codex одного аккаунта-подписки, ответ возвращается как есть. Аккаунт выбирает общий балансировщик среди ChatGPT-аккаунтов ключа. Правка, которая ссылается на `file_id`, идёт только на аккаунт-владелец файла.
- С ключа списывается по токенам из ответа (`usage`) по ставкам модели картинок. Резерв берётся до отправки и закрывается один раз. Ответ без `usage` остаётся в резерве до сверки.
- Для картинок у ChatGPT свой дневной лимит (`x-codex-active-limit: imagegen_premium`). Поэтому запросы картинок не меняют состояние и квоту аккаунта, ни при успехе, ни при отказе.
- Если аккаунт отказал по лимиту картинок (429) до выдачи результата, запрос уходит на другой аккаунт, всего пробуется не больше 4 аккаунтов. Отказавший аккаунт 10 минут не получает запросов картинок.
- В журнале запросов это виды `image_generation` и `image_edit` с моделью из запроса. В диагностике ошибок сами картинки не сохраняются.
- Добавлены встроенные цены `gpt-image-2.5-flare` и `gpt-image-2.5-sunburst` (как у `gpt-image-2`).
- Редакция токена в ответах операций больше не пересобирает JSON, когда токена в теле нет. Многомегабайтные картинки проходят без лишней сериализации.

## Настройка Codex

Codex показывает инструмент картинок при одном из двух вариантов настройки провайдера:

- `requires_openai_auth = true` и вход в Codex через ChatGPT. Ключ codex-lb по-прежнему берётся из `env_key`.
- `requires_openai_auth = false` и в `http_headers` провайдера непустой `x-openai-actor-authorization`, например `"codex-lb"`. Это только метка возможности: codex-lb её не проверяет и дальше не передаёт.

После смены настроек нужна новая сессия Codex.

## Обновление

Схема SQLite не меняется (**43**), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.5.1 обновление из **Settings → Runtime updates** проходит без простоя.

## Проверки и ограничения

- Прошли `go vet`, `golangci-lint`, полный `go test` и `go test -race` (в CI четырьмя шардами), `govulncheck`, тесты дашборда и `openspec validate`.
- Маршрутные тесты с локальной заглушкой ChatGPT проверяют:
  - пересылку без изменений и списание один раз;
  - перевод multipart в JSON;
  - отказ некорректных запросов до отправки;
  - политику моделей ключа;
  - переход на другой аккаунт при лимите картинок без изменения состояния аккаунтов;
  - закрепление правки за владельцем файла;
  - отсутствие картинок в диагностике.
- Прямые запросы к подписке 29.10.2026 показали: images-эндпоинт ChatGPT принимает любые `model`, `quality`, `size` и параметры рассуждений, но игнорирует их и всегда отдаёт 1254×1254 с качеством `low`. По анонсу OpenAI ChatGPT и Codex на всех тарифах уже используют Картинки 2.5.
- Выбрать модель (GPT Image 2.5 Sunburst или Flare), качество или размер через подписки нельзя. Это возможно только через OpenAI API, и это отдельная доработка.
- Потоковые ответы картинок (`stream: true`) не поддерживаются: Codex их не использует.
- Токены входных картинок у правок считаются по ставке текстового ввода.
- Публикация релиза сама по себе не обновляет сервер.
