# Go v1.10.6 — чтение срока подписки проходит Cloudflare

## Изменения

- В go-v1.10.5 ни один аккаунт не получил срок подписки из ChatGPT: Cloudflare отвечал на `GET /backend-api/subscriptions` от стандартного клиента Go страницей проверки (403, `cf-mitigated: challenge`), и страница **Accounts** показывала дату из токена.
- Теперь этот запрос отправляет те же заголовки клиента Codex, что и чтение каталога моделей: `Originator: codex_cli_rs` и `User-Agent: codex_cli_rs/<версия клиента Codex из настроек>`. Запросы использования и reset credits не менялись.

## Обновление

Схема SQLite не меняется (48), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.10.5 обновление из **Settings → Runtime updates** проходит без простоя. Сроки появятся после первого опроса новой версии, примерно через минуту.

## Проверки и ограничения

- Гейты прогнаны локально: `go vet`, `golangci-lint`, `go test`, `go test -race` (четыре шарда), `govulncheck`, тесты дашборда, сборка, контрактные тесты и `openspec validate`.
- Причина подтверждена диагностикой с прода с разрешения владельца: два запроса с токеном одного аккаунта, без Codex-заголовков — 403 с проверкой Cloudflare, с ними — 200 и `active_until`.
- Неудачные чтения срока в журнал не пишутся. Если провайдер снова начнёт отказывать, это будет видно только по `subscription: null` в `GET /api/accounts` и по дате из токена на странице.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
