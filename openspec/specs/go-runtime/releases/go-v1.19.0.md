# Go v1.19.0 — транспорт Antigravity с профилем Chrome 123

## Изменения

- Все запросы codex-lb к Google по источникам Antigravity — инференс Cloud Code, контрольные вызовы (`loadCodeAssist`, `onboardUser`, `fetchAvailableModels`) и OAuth (токен, userinfo) — теперь идут через транспорт с отпечатком **Chrome 123**, как в Antigravity-Manager (`rquest Emulation::Chrome123`): TLS ClientHello захваченного Chrome со случайным порядком расширений, ECH GREASE, PSK и ALPS `h2`; настройки HTTP/2 `1:65536, 2:0, 4:6291456, 6:262144`, прирост окна соединения `15663105`, порядок псевдо-заголовков `:method,:authority,:scheme,:path`. Реализация — `internal/adapters/chromeprofile` на `bogdanfinn/tls-client` v1.16.0 (захват Chrome 120, побайтово совпадающий с Chrome 123).
- Заголовки и User-Agent не изменились: как и в менеджере, Google по-прежнему видит `antigravity/hub/<версия> (aidev_client; os_type=windows; arch=amd64; cl=1023160026)` и только `Content-Type`, `Authorization`, `User-Agent`. Отпечаток живёт только в транспорте. Прочие провайдеры (OpenAI, ChatGPT, Z.AI, Grok) ходят через прежний общий транспорт.
- Egress-guard и прокси сохранены: закрытые адреса блокируются при дозвоне, прокси окружения используется через CONNECT-туннель (кэш клиентов по прокси-эндпоинтам, лимит 4).
- Починен сломанный go-v1.18.0-коммит `9a3ec581`: неиспользуемый `import "runtime"` (не собирался `go build`), тесты со старым форматом User-Agent, дефолт версии в дашборде.
- Решение владельца (2026-11-22): граница «без эмуляции отпечатков» из go-v1.17.0 снята для транспорта; перезапись промптов и нативные поля запросов по-прежнему исключены. Спеки: `specs/antigravity-accounts.md` (R4), `specs/antigravity-chrome-transport.md`.

## Обновление

Миграция 54 корректирует сид `runtime_settings.antigravity_client_version` с `2.34.0` (выдуманная версия из миграции 53) на реальную версию Antigravity Hub `2.33.0`. Она аддитивная и мгновенная; версия, сохранённая оператором в Settings, не трогается, если не равна старому сиду. Обновление из **Settings → Runtime updates** с go-v1.2.0 – go-v1.18.0 проходит без простоя. Протоколы обновления и передачи не менялись.

## Проверки и ограничения

- Гейты прогнаны локально и в CI: `go vet`, `golangci-lint`, `go test`, `govulncheck`, тесты дашборда, контрактные тесты на собранном бинарнике. Зависимости подняты до закрытия уязвимостей govulncheck: `brotli v1.2.7`, `klauspost/compress v1.20.2`, `circl v1.6.3`.
- Тесты проверяют: сквозную доставку запроса через новый транспорт (метод, путь, заголовки, тело — без добавлений), CONNECT-туннель прокси, отмену по контексту, TLS-соединение, константы профиля против менеджера; что вызовы Cloud Code уходят через выделенный клиент, а не общий.
- Реальный трафик к Google в тестах не используется; поведение отпечатка на живых эндпоинтах проверяйте на своей установке.
- Релиз собран в CI и не подписан отдельным ключом.
- Публикация релиза сама по себе не обновляет сервер.
