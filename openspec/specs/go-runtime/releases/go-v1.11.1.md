# Go v1.11.1 — запросы Codex к Grok проходят

## Изменения

- В go-v1.11.0 источник Grok отклонял запросы Codex CLI ещё до xAI (`unsupported_capability`), и Codex повторял их впустую. Codex CLI не читает каталог codex-lb и для любой модели присылает свои настройки рассуждения, MCP-инструменты в виде `namespace` и поиск `web_search`. Шесть проб с прода с разрешения владельца показали, что из этого xAI не принимает.
- Теперь запрос к источнику Grok приводится к тому, что xAI принимает:
  - инструменты `namespace` разворачиваются в обычные функции `<namespace>-<имя>`, а вызовы в ответе возвращаются к Codex с исходным именем и namespace;
  - у `web_search` остаются только поля, которые знает xAI. Поиск только по кэшу (`external_web_access: false`, так Codex шлёт по умолчанию) не передаётся: xAI ищет только в живом вебе;
  - уровень рассуждения подгоняется под модель: `grok-4.7` и `grok-4.6` принимают до `xhigh`, `grok-4.5` до `high`, поэтому `max` уходит как наивысший доступный уровень. Остальным моделям (`grok-build-0.1`, `grok-4.3`, `grok-4.20`) уровень не передаётся: xAI его у них не принимает;
  - остальные поля, включая `summary`, `include` и `prompt_cache_key`, передаются без изменений.
- Новые источники Grok объявляют в каталоге уровни рассуждения для `grok-4.7`, `grok-4.6` и `grok-4.5`.

## Обновление

Схема SQLite не меняется (48), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.11.0 обновление из **Settings → Runtime updates** проходит без простоя. Источник, созданный на go-v1.11.0, пересоздавать не нужно: подгонка запросов работает по имени модели. Без пересоздания в каталоге только не будет уровней рассуждения, а Codex CLI каталог всё равно не читает.

## Проверки и ограничения

- Гейты прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `go test -race` (четыре шарда, как в CI), `govulncheck`, тесты дашборда, сборка, контрактные тесты и `openspec validate`.
- Заглушка xAI в тестах отклоняет то же, что отклонил настоящий xAI. Сквозной тест отправляет запрос в форме Codex CLI и проверяет, что вызов MCP-инструмента возвращается к клиенту с namespace.
- Пробы шли на `grok-4.7` и `grok-build-0.1`. Принимают ли `grok-4.3` и `grok-4.20` поле `include` с зашифрованным рассуждением, не проверялось.
- Если Codex разрешает живой поиск, xAI выполняет его на своей стороне. Такие поиски xAI тарифицирует отдельно, и в расчёт codex-lb они не попадают.
- Окно контекста у источника 256 000 токенов. Если в `config.toml` задан больший `model_context_window`, Codex будет считать окно больше настоящего.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
