# Go v1.7.1 — окна активного лимита картинок в заголовках сброса

## Изменения

- При отказе по лимиту картинок клиенту теперь приходят и собственные окна активного лимита: заголовки `X-<id лимита через дефис>-*`, например `X-Imagegen-Premium-*` для `imagegen_premium`. Такой id лимита сообщают аккаунты Pro.
- Как и в go-v1.7.0, клиент получает `Retry-After`, `X-Codex-Active-Limit`, `X-Image-Gen-*` и окна `X-Codex-Primary-*` / `X-Codex-Secondary-*`. Заголовки плана и кредитов аккаунта по-прежнему не передаются.
- Это касается итогового 429 на маршрутах `/images/*` и отказа по лимиту картинок на `/responses`.
- Go SDK форка Codex (sdk/go/v0.165.3) читает время сброса сначала из `x-<limit>-*`. В go-v1.7.0 эти заголовки отбрасывались.

## Обновление

Схема SQLite не меняется (**43**), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.7.0 обновление из **Settings → Runtime updates** проходит без простоя. Если прод ещё на go-v1.6.0, можно сразу ставить go-v1.7.1: он содержит всё из go-v1.7.0.

## Проверки и ограничения

- Прошли `go vet`, `golangci-lint`, полный `go test` и `go test -race`, `govulncheck`, сборка дашборда, контрактные тесты и `openspec validate`. Всё прогнано локально, потому что CI на GitHub недоступен.
- Тесты проверяют выбор заголовков для `imagegen_premium` и итоговый 429 маршрута картинок.
- Сами заголовки `x-imagegen-premium-*` напрямую не наблюдались: исчерпания лимита на проде не было. Схема имён взята из того, как их читают клиенты Codex.
- Публикация релиза сама по себе не обновляет сервер.
