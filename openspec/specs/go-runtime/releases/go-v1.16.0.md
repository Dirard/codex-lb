# Go v1.16.0 — аккаунты, которые не отдают свои разговоры

## Изменения

- У любого аккаунта появилась опция «Keep conversations here» (`stickyOnly`). Она есть в карточке аккаунта на странице аккаунтов и переключателем «Sticky» в строке источника модели.
- Аккаунт с этой опцией остаётся в балансировке: новые разговоры на него по-прежнему назначаются. Но разговор, который начался на нём, не переезжает на другой аккаунт, когда у этого аккаунта кончается лимит. Клиент получает отказ по лимиту, а следующий ход снова идёт на тот же аккаунт.
- Отказ по лимиту в таком разговоре приходит как HTTP 429 (или кадр ошибки WebSocket) с типом и кодом `usage_limit_reached`. Codex показывает его как исчерпанный лимит, а не как проблему с оплатой.
- Разговор, который уже был помечен отказом по квоте до включения опции, тоже остаётся на своём аккаунте.
- Первый запрос нового разговора при отказе по квоте по-прежнему переходит на другой аккаунт: разговор на исчерпанном аккаунте ещё не начался.
- Компакция разговора с таким аккаунтом тоже не переносится на другой аккаунт.
- Отказ учитывается как и раньше: без списания, если ничего не было показано, и отмечается у аккаунта, чтобы новые разговоры обходили исчерпанный аккаунт.
- `PATCH /api/accounts/{id}` принимает `stickyOnly`, а список аккаунтов и источники моделей его возвращают.

## Обновление

Миграция 52 добавляет столбец `accounts.sticky_only` со значением по умолчанию 0. Она аддитивная и проходит мгновенно, поэтому обновление из **Settings → Runtime updates** с go-v1.2.0 – go-v1.15.1 проходит без простоя. У всех существующих аккаунтов опция выключена, поведение не меняется, пока её не включить. Протоколы обновления и передачи не менялись.

## Проверки и ограничения

- Гейты прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `go test -race`, `govulncheck`, `openspec validate`, тесты дашборда, сборка и контрактные тесты на собранном бинарнике.
- Тесты на маршруте `/backend-api/codex/responses` через настоящий адаптер провайдера и SQLite проверяют три случая. Для аккаунта с опцией отказ по квоте приходит клиенту, второй аккаунт не вызывается, разговор не помечается, следующий ход возвращается на тот же аккаунт. Обычный аккаунт переносит разговор, как раньше. Новый разговор с аккаунта с опцией переходит на другой аккаунт. Ещё два теста: ранее помеченный разговор и компакция на `/v1/responses/compact`.
- Голосовые звонки и так никогда не переносили закреплённый разговор, а картинки не являются разговорами, поэтому для них ничего не менялось.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
