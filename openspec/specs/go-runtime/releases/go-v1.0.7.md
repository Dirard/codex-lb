# codex-lb Go 1.0.7

## Исправление обрывов при долгом ожидании модели

Native WebSocket `/backend-api/codex/responses` снова получает служебные текстовые сообщения каждые 10 секунд: `codex.keepalive` до получения настоящего ID ответа и `response.in_progress` с этим ID после. Это устраняет отсутствие keepalive в Go-версии, из-за которого Codex мог переподключаться по stream-idle timeout во время долгого reasoning.

Heartbeat не считается выводом модели или расходом, не мешает безопасному переключению по квоте и прекращается после завершения/отмены. У публичного `/v1/responses` синтетические сообщения не добавляются.

Живость активного upstream WebSocket проверяется отдельно: ping раз в 30 секунд, до 10 секунд на pong. Потерянное соединение завершается без слепого повторения генерации. Pong не считается прогрессом модели и не продлевает общий таймаут ответа — по умолчанию 2 часа. Короткого ограничения на длительность reasoning не добавлено.

## Исправление распределения сабагентов

Новые независимые треды с разными `Thread-Id` больше не наследуют один аккаунт из-за общего `prompt_cache_key`. Внутренняя привязка кэша LB теперь учитывает API-ключ, `Session_id` и `Thread-Id`; сам ключ кэша передаётся провайдеру без изменений.

Исправление действует для HTTP/SSE, WebSocket и compact. Оно также не позволяет новым тредам подхватить старую общую привязку, сохранённую до обновления. Клиенты без `Thread-Id` сохраняют прежнее поведение кэша, включая работу при выключенном Sticky threads.

## Важные ограничения

- Уже работающие треды не переселяются на другие аккаунты. Подтверждённое владение ответом, сессией, turn state или файлом сохраняется; перенос по-прежнему возможен только по существующим безопасным правилам после ошибки квоты от upstream. Продолжение при 0% без такого отказа не блокируется этим изменением.
- `Capacity weighted` остаётся вероятностным выбором, а не обещанием равного числа запросов на каждый аккаунт.
- **`Prefer earlier reset` не изменён.** Если он включён, строгий приоритет ближайшего сброса всё ещё может сузить выбор до одного аккаунта. Для распределения по всему допустимому набору без этого приоритета настройку можно отключить в админке; публикация релиза сама её не меняет.
- Сохраняются ограничения ключей, групп, моделей, доступности и ёмкости аккаунтов. Запросы с одинаковой логической идентичностью не объявляются разными агентами по названию роли.
- Реальные обрывы upstream после начала выдачи ответа (`stream_incomplete`, `upstream_error`, часть 502) не объявляются исправленными этим релизом. Heartbeat не восстанавливает потерянный результат и не разрешает повторно выполнять инструменты. Неизвестный расход по-прежнему требует reconciliation.

## Обновление и проверки

Относительно `go-v1.0.6` схема SQLite (33), протокол обновления (1) и конфигурация не меняются. Можно обновиться через **Settings → Runtime updates** или заменить бинарник вручную, сохранив каталог данных и ключ шифрования. Перед ручным обновлением сделайте согласованную резервную копию. Старые cache bindings не удаляются; для них сохраняются прежние правила TTL.

Архивы Linux amd64 и arm64 содержат статический `codex-lb` со встроенной админкой, лицензии и необязательный шаблон systemd. Проверьте `SHA256SUMS`; команда `./codex-lb version` должна показать `go-v1.0.7`. Arm64 кросс-компилируется; запуск на ARM-устройстве не заявляется.

Локальные тесты с шестью аккаунтами проверяют независимое распределение через HTTP/WebSocket, compact, сохранение владельцев при 0% квоты, неизменность provider-facing cache key и однократный учёт расходов. WebSocket-регрессии проверяют молчание до/после created, оба native/v1 пути, quota failover после heartbeat, отмену/отключение клиента, отсутствие кадров после terminal, отзывчивый и не отвечающий на pong upstream, общий deadline и сохранение continuation после завершения во время ping. Платные запросы к провайдерам и production soak не выполнялись.

Прошли полные `go test ./...`, `go test -race ./...`, `go vet ./...`, сборка UI и 11 офлайн-интеграционных проверок собранного бинарника. Новые проверки потоков дополнительно пройдены трижды под `-race`; заключительное независимое ревью блокирующих ошибок не нашло. Актуальная спецификация Go и delta изменения прошли строгую проверку.

Публикация не обновляет локальный рабочий сервис или VPS.
