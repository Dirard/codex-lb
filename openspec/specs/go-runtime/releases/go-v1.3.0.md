# Go v1.3.0 — быстрые отчёты и обзор по группам

## Быстрая аналитика

- Отчёты больше не пересчитываются из сырых событий на каждый запрос. Фоновый процесс складывает события в почасовые агрегаты: итоги, разрезы по ключу, аккаунту, модели и user-agent, коды ошибок, беседы, фасеты журнала запросов. Любое изменение уже сложенного события — пересчёт цен, ретенция, удаление истории аккаунта — попадает в журнал агрегатов триггерами. Поэтому агрегаты не расходятся с событиями, даже пока при обновлении работает предыдущая версия.
- Каждый отчёт собирается в одном снимке базы из агрегатов, ещё не сложенного хвоста и сырых краёв неполных часов. Результат точный, кроме дневных медиан TTFT, очереди и токенов в секунду: они считаются по гистограммам с относительной погрешностью не больше 1/64. Стоимость суммируется в целых микродолларах, поэтому на округлениях возможны расхождения до $0,0001 с прежними цифрами.
- Если агрегаты отстают или их формат не совпадает, отчёты считаются по-старому, из сырых событий. Раз в час сверка сравнивает оба способа и при расхождении перестраивает агрегаты.
- На копии рабочей базы (768 тыс. событий): обзор за 7/30 дней — 5,2/14,6 с → 0,22/0,26 с, отчёты за 30 дней — 8,0 с → 0,14 с, отчёт ключа — 0,84 с → 0,035 с, беседы за 7 дней — 1,35 с → 0,06 с.
- Журнал запросов и его фильтры: зависшие резервы читаются из нового частичного индекса. В бенчмарке с 74 тыс. зависших резервов и 742 тыс. событий фильтры ускорились с 0,2/2,8 с до 0,014/0,22 с (warm/cold), первая страница — с 0,19/2,8 с до 0,045/0,49 с.

## Обзор по группам

- Вместо прежнего дашборда — страница **Обзор**, рассчитанная на десятки групп и сотни ключей. Сверху тревоги: аккаунты, которым нужен повторный вход; квота пула или группы, которая закончится до сброса при текущем темпе; ключи на 90 % и 100 % лимита; всплески ошибок; ключи, которые истекают через 7 дней или через сутки; устаревшие данные квот.
- Ниже — полоса пула и таблица групп: здоровье аккаунтов, остаток 5 ч и недельной квоты со сбросом и прогнозом, заполнение лимитов группы, ключи, расход сегодня и тренд за 7 дней. Группы, которым нужно внимание, идут первыми, строка раскрывается до проблемных аккаунтов и топ-ключей. Ключи без группы — отдельной строкой. Внизу — 10 ключей, требующих внимания, у каждого есть действие.
- Переключателя периода нет: у каждой цифры подписан свой период.
- Журнал запросов и беседы переехали на страницу **Запросы** с одним переключателем периода (по умолчанию 24 ч). Опроса нет, пока не включён Live.
- Навигация: Обзор · Группы · Аккаунты · Ключи · Отчёты · Автоматизации · Настройки. Глобальный поиск по Ctrl/Cmd+K находит ключи, группы, аккаунты и id запросов. Каждая страница делает не больше одного периодического запроса, шапка и строка состояния берут данные из него.
- Новые эндпоинты: `GET /api/overview`, `GET /api/directory`, `GET /api/api-keys/{id}`. `GET /api/dashboard/status` получил дополнительные поля. Страницы отдают заголовок `Server-Timing`.

## Зависшие резервы

- Резервы, ждущие сверки дольше часа (прерванный процесс или ответ без usage), теперь освобождаются без списания. Это решение владельца. Лимиты ключей возвращаются в пределах текущего окна, события usage не записываются, отчёты не меняются. Освобождение идёт пакетами по 100 в пределах 5 с на минутный проход, так что ~74 тыс. накопленных резервов уйдут примерно за полчаса после обновления.

## Исправления

- WebSocket: `response.cancel` во время отправки кадра больше не закрывает сессию клиента. Раньше клиент получал обрыв вместо ошибки хода и переподключался; пока ответ стримился, так было почти при каждой отмене.
- Бюджет тел запросов: параллельные запросы с объявленным `Content-Length`, которые вместе помещаются в бюджет, больше не получают ложный 503 `local_capacity_exceeded`. Раньше чтение тела временно резервировало до 64 КиБ сверх его длины.

## Устарело

- `GET /api/dashboard/overview` и `GET /api/dashboard/projections` встроенный интерфейс больше не вызывает. В этом релизе они работают без изменений и будут удалены не раньше следующего. `/v1/usage`, `/api/codex/usage` и `/v1/usage/reports` не меняются.

## Обновление

Схема SQLite **43**: две аддитивные миграции. 42 создаёт пустые таблицы агрегатов, журнал и триггеры (миллисекунды). 43 строит частичный индекс зависших резервов (0,2–0,4 с на 1,6 млн резервов). Нижняя граница совместимой схемы остаётся 40. Протоколы обновления и передачи не меняются.

С go-v1.2.0 обновление из **Settings → Runtime updates** проходит бесшовно: миграции выполняются, пока предыдущая версия ещё обслуживает запросы. После переключения фоновый процесс около минуты складывает существующие события в агрегаты (61 с на копии рабочей базы); в это время отчёты считаются по-старому, из сырых событий. Откат на go-v1.2.0 тоже бесшовный и не требует восстановления бэкапа.

## Проверки и ограничения

Прошли `go vet`, `golangci-lint`, полный `go test` и `go test -race` (в CI — четырьмя параллельными шардами), `govulncheck`, тесты, lint и typecheck дашборда, контрактные тесты API на собранном бинарнике, `openspec validate`. Чтение из агрегатов сверено с чтением из сырых событий рандомизированными тестами по фильтрам, шести часовым поясам (переходы на летнее время, смещения на полчаса и 45 минут) и четырём состояниям свёртки. На копии рабочей базы ответы обоих путей совпали побайтно для 17 эндпоинтов из 18; восемнадцатый, прогнозы, зависит от текущего времени. Реальные провайдеры не использовались. Публикация релиза сама по себе не обновляет сервер.
