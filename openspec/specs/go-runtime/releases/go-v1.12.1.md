# Go v1.12.1 — голос из браузера с любого домена

## Изменения

- В go-v1.12.0 веб-страница с другого домена не могла пользоваться голосом напрямую, даже с секретом `ek_`. Защита от междоменных запросов отклоняла `POST /v1/realtime/calls`, а голосовой WebSocket принимал только свой Origin.
- Теперь браузер может работать с голосом сам, без своего бэкенда:
  - голосовая сессия `wss://<host>/v1/realtime?model=…` принимает подключение с любого Origin. Ключ передаётся только явно, Bearer-заголовком или подпротоколом `openai-insecure-api-key.ek_…`, поэтому чужая страница без ключа или секрета ничего не получит;
  - `POST /v1/realtime/calls` отвечает на CORS-предзапрос (`OPTIONS`) и отдаёт `Access-Control-Allow-Origin: *` и `Access-Control-Expose-Headers: Location`. Страница может отправить SDP-оффер с `Authorization: Bearer ek_…` и прочитать ответ и адрес звонка.
- Остальные маршруты защищены как раньше: сайдбенд звонка, голос Codex, выдача секретов `/v1/realtime/client_secrets` и все прочие прокси-маршруты.

## Обновление

Схема SQLite не меняется (49), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.12.0 обновление из **Settings → Runtime updates** проходит без простоя.

## Проверки и ограничения

- Гейты прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `go test -race` (четыре шарда, как в CI), `govulncheck`, тесты дашборда, сборка, контрактные тесты и `openspec validate`.
- Тесты идут через полный обработчик сервера с той же защитой, что на проде. Страница с `https://app.example` открывает сессию по секрету и создаёт звонок, а выдача секретов, `/v1/responses` и сайдбенд для неё закрыты.
- В настоящем браузере это ещё не проверялось.
- Секрет `ek_` выдаётся только с сервера по ключу codex-lb. Ключ codex-lb в браузер не передавайте.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
