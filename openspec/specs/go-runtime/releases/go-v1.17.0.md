# Go v1.17.0 — аккаунты Google Antigravity

## Изменения

- Аккаунты Google Antigravity можно добавлять в пул. На странице **Model sources** есть кнопка «Add Antigravity account»: откройте ссылку, войдите в Google, вставьте полученный код или весь адрес страницы. Аккаунт становится источником модели вида `antigravity`. Его модели (Gemini 4, Gemini 3.8 Flash, Claude 5.5 и другие, какие даёт тариф) появляются в каталоге Codex и обслуживают запросы Responses и Chat Completions.
- Новый аккаунт Antigravity создаётся с ценой 0 у всех моделей и с включённой опцией «Keep conversations here»: разговор остаётся на своём аккаунте. Цены можно задать в диалоге источника.
- Хранение данных:
  - refresh-токен Google хранится зашифрованным;
  - email, проект Cloud Code, тариф и ссылка на апелляцию или подтверждение видны в карточке источника;
  - токены нигде не показываются и не пишутся в журнал.
- Запросы переводятся в протокол Cloud Code `v1internal:streamGenerateContent` и обратно:
  - тексты, картинки во входе, вызовы инструментов и их результаты;
  - размышления модели;
  - подписи размышлений, которые возвращаются модели в следующих ходах;
  - учёт токенов: выход = `candidatesTokenCount + thoughtsTokenCount`.
- Отказы Google различаются:
  - исчерпание квоты считается отказом по квоте (для аккаунта с «Keep conversations here» клиент получает `usage_limit_reached`);
  - превышение частоты и нехватка мощностей — временные отказы с `Retry-After`;
  - 429 без подробностей (так Google отклоняет запрос из-за его содержимого) приходит клиенту как `upstream_content_refused` и аккаунт не трогает;
  - приостановка за нарушение условий (`TOS_VIOLATION`) выключает аккаунт и показывает ссылку на апелляцию;
  - требование подтвердить аккаунт переводит его в повторный вход со ссылкой.
- В карточке источника есть «Re-authorize» (повторный вход того же email; модели, цены и опции сохраняются) и «Refresh models».
- User-Agent запросов к Google собирается из версии клиента Antigravity в `CODEX_LB_ANTIGRAVITY_CLIENT_VERSION` (по умолчанию `2.34.0`), так же как codex-lb представляется Codex. codex-lb не подделывает отпечатки TLS или HTTP и не переписывает промпты, чтобы обойти фильтры Google.

## Обновление

Схема SQLite не меняется (52), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.16.0 обновление из **Settings → Runtime updates** проходит без простоя. Сохранение источника больше не снимает приостановку аккаунта; для прочих источников поведение прежнее.

## Проверки и ограничения

- **Риск блокировки.** Условия Antigravity (раздел 6) считают доступ через сторонние программы нарушением. В ноябре 2026 года Google приостанавливал такие аккаунты, апелляция даётся один раз. Владелец принял этот риск. Системный промпт Codex может срабатывать на фильтр Google — тогда клиент получит `upstream_content_refused`.
- **Гейты.** Прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `go test -race`, `govulncheck`, `openspec validate`, тесты дашборда, сборка и контрактные тесты на собранном бинарнике.
- **Тесты.** Работают через loopback-заглушки Google, запросов к Google не было:
  - вход через админ-маршруты;
  - ход Codex с вызовом инструмента и повтором подписи на следующем ходе;
  - отказ по квоте на аккаунте с «Keep conversations here»;
  - приостановка, после которой аккаунт больше не используется;
  - каждый вид отказа;
  - обновление токена;
  - повторный вход.
- **Подписи размышлений.** Хранятся в памяти процесса. После перезапуска или обновления неизвестный вызов Gemini получает служебную метку вместо подписи, а история Claude идёт без размышлений.
- **Квоты.** Окна квот Antigravity (5 часов и неделя) пока не показываются и не участвуют в балансировке.
- **Сборка.** Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
