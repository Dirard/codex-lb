# Go v1.20.1 — честная ошибка для моделей сторонних провайдеров

## Изменения

- **«No price is configured» вместо «модель недоступна».** Запрос к модели, которую источник не обслуживает (например, модель ChatGPT на ключе, где из доступных аккаунтов остался только источник Z.AI), получал `model_not_priced`, хотя цены у моделей источника заданы. Теперь такой источник не считается кандидатом, и клиент получает 404 `model_not_available` («No permitted account supports the requested model») по HTTP и в WebSocket. `model_not_priced` остаётся только для модели, которую аккаунт обслуживает, но цены у неё нет.
- **Диалог правки источника.** Он показывает один набор настроек, применяемый ко всем моделям из списка, но новая модель в списке получала только изменённые поля. Так на проде `glm-5.4` сохранилась без цены, лимитов контекста, размышлений и инструментов. Теперь добавленная модель получает все настройки, видимые в форме.

## Обновление

Схема SQLite не меняется (55), протоколы обновления и передачи тоже. Обновление из **Settings → Runtime updates** проходит без простоя.

Уже сохранённая модель с пустыми настройками сама не исправится. Откройте источник, уберите её из списка и сохраните, затем добавьте снова и сохраните ещё раз: при повторном добавлении она получит настройки из формы.

## Проверки и ограничения

- Гейты прогнаны локально, а не в CI: `go vet`, `golangci-lint`, `go test`, `govulncheck`, `openspec validate`, тесты дашборда, сборка и контрактные тесты на собранном бинарнике.
- Регрессионный тест на маршруте `/backend-api/codex/responses` по HTTP и WebSocket повторяет сбой: до исправления он получал 400 `model_not_priced`. Тест дашборда проверяет, что добавленная модель сохраняется с ценой и прочими настройками формы.
- Релиз собран вручную и не подписан: ключ подписи есть только в CI.
- Публикация релиза сама по себе не обновляет сервер.
