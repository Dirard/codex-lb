# Go v1.7.2 — отменённые запросы дашборда не считаются ошибками

## Изменения

- Если браузер оборвал запрос дашборда, например при кратком сбое сети, codex-lb теперь отвечает 499 `request_cancelled` и не пишет в журнал `admin operation failed` с уровнем ERROR. Раньше такой запрос давал 500 `internal_error` и строку ERROR, и сбой сети у клиента выглядел как поломка сервера.
- Прочие неожиданные ошибки API дашборда по-прежнему дают 500 `internal_error` и пишутся в журнал.
- Код 499 уже используется для отменённых запросов к прокси. Теперь у дашборда та же константа.

## Обновление

Схема SQLite не меняется (**43**), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.7.1 обновление из **Settings → Runtime updates** проходит без простоя.

## Проверки и ограничения

- Прошли `go vet`, `golangci-lint`, полный `go test` и `go test -race`, `govulncheck`, сборка дашборда, контрактные тесты и `openspec validate`. Всё прогнано локально, потому что CI на GitHub недоступен.
- Регрессионный тест на маршруте `/api/accounts` проверяет три случая:
  - отменённое чтение даёт 499 без строки в журнале;
  - то же, если отмена обёрнута в другую ошибку;
  - другая ошибка, как и раньше, даёт 500 и строку в журнале.
  Без исправления тест падает.
- Публикация релиза сама по себе не обновляет сервер.
