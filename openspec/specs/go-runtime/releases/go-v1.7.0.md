# Go v1.7.0 — поток и время сброса лимита картинок

## Изменения

- Маршруты картинок (`/backend-api/codex/images/*`, `/v1/images/*`) принимают `stream: true`. Запрос уходит в ChatGPT с `Accept: text/event-stream`.
  - Если подписка отвечает потоком, codex-lb пересылает события как есть, по мере поступления. Сейчас для генерации это `keepalive` примерно раз в 15 с и одно `image_generation.completed` с картинкой, `usage`, `quality`, `size` и `generation_id`. Списание идёт по `usage` из завершающего события.
  - Если подписка отвечает JSON, как сейчас бывает для `edits`, клиент получает JSON.
  - Поток, закончившийся без картинки, завершается событием `error`. Резерв в этом случае остаётся до сверки.
  - Недопустимым остаётся только `stream`, который не булев.
- Итоговый отказ 429 по лимиту картинок приходит клиенту с заголовками сброса из ChatGPT: `Retry-After`, `X-Codex-Active-Limit`, все `X-Image-Gen-*`. Если активный лимит — лимит картинок, добавляются ещё окна `X-Codex-Primary-*` и `X-Codex-Secondary-*`. Заголовки плана и кредитов аккаунта клиенту не передаются.
- `/backend-api/codex/responses` и `/v1/responses` с hosted-инструментом `image_generation`: отказ 429, у которого `X-Codex-Active-Limit` называет лимит картинок (`image_gen`, `imagegen_premium`), больше не считается исчерпанием квоты аккаунта.
  - Аккаунт не помечается `quota_exceeded` и остаётся в работе для чата.
  - Запрос не переносится на другой аккаунт.
  - Попытка закрывается без оплаты.
  - Клиент получает 429 с `error.type` и `error.code` `usage_limit_reached` и теми же заголовками сброса. Раньше в этом случае приходил 503 `no_available_accounts`.
  - В журнале запросов такая ошибка записывается с кодом `image_generation_limit`.

## Обновление

Схема SQLite не меняется (**43**), протоколы обновления и передачи тоже. С go-v1.2.0 – go-v1.6.0 обновление из **Settings → Runtime updates** проходит без простоя.

## Проверки и ограничения

- Прошли `go vet`, `golangci-lint`, полный `go test` и `go test -race`, `govulncheck`, сборка дашборда, контрактные тесты и `openspec validate`. CI на GitHub недоступен, поэтому всё прогнано локально. Дашборд в этом релизе не менялся.
- Маршрутные тесты проверяют:
  - пересылку потока без изменений и списание один раз;
  - JSON-ответ на поточную правку;
  - поток без картинки;
  - заголовки сброса при итоговом 429 без заголовков плана;
  - отказ по лимиту картинок на `/responses`: аккаунты остаются активными, перенос и резерв не остаются;
  - обычный отказ по квоте, который по-прежнему помечает аккаунт.
- Проба 30.10 на Pro показала, что подписка игнорирует `partial_images`, поэтому черновых кадров нет. Правка с `stream: true` отвечает JSON.
- Как подписка сообщает об исчерпанном лимите картинок на `/responses`, напрямую не наблюдалось: на проде таких отказов не было. Распознаётся именно 429 с `X-Codex-Active-Limit`. Сбой картинки внутри уже начатого потока Responses не распознаётся.
- Публикация релиза сама по себе не обновляет сервер.
