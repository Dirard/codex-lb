# Go v1.1.1 — исправление цикла ретенции
<!-- prerelease -->

## Исправления

- Цикл ретенции больше не завершается с ошибкой после прореживания истории квот. Последний интервал прореживания заканчивался на границе, обрезанной до миллисекунд, и при точности часов выше миллисекунды получался пустой интервал. В журнале каждый час появлялось `report retention did not complete … "failed":["quota_history_thinning"]`, а метрики считали цикл неудачным. Данные не затрагивались.

## Обновление

Как для go-v1.1.0: схема SQLite **40**, протокол обновления **1**. Релиз опубликован как pre-release, чтобы его не видел апдейтер go-v1.0.10. Сначала обновитесь до **go-v1.0.11**; после перевода этой версии в обычный релиз go-v1.0.11 предложит её в **Settings → Runtime updates** — со всеми изменениями go-v1.1.0 и их подготовкой (см. [заметки go-v1.1.0](https://github.com/Dirard/codex-lb/releases/tag/go-v1.1.0)).

## Проверки и ограничения

Регрессионный тест на настоящей SQLite с часами субмиллисекундной точности падал до исправления и проходит после; полный CI (`go vet`, `golangci-lint`, `go test`, `go test -race`, `govulncheck`, проверки дашборда, OpenSpec) зелёный. Реальные провайдеры не использовались.
