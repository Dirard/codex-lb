# Обновление и откат из админки

## Why

Администратору нужны кнопки «Обнаружена новая версия — обновить» и «Откатить до предыдущей версии» без SSH и ручной замены бинарника. Механизм должен работать независимо от systemd, Docker и других способов запуска, сохраняя данные и текущие запросы.

## What Changes

- Проверка стабильных Go-релизов Dirard/codex-lb и показ версии, доступности обновления, прогресса и результата в админке.
- Встроенный управляющий запуск того же бинарника: непривилегированный родитель управляет одним серверным дочерним процессом и сохраняет проверенные версии в приватном каталоге данных.
- Загрузка и проверка артефакта до переключения, ожидание безопасного завершения запросов, короткий перезапуск на прежнем адресе и проверка готовности.
- Ручной откат к сохранённой версии и автоматическое восстановление прежней версии при неудачном старте; БД и ключ шифрования не откатываются.
- Первая версия разрешает автоматическую установку только для совместимых протокола обновления и идентичной схемы БД. Неподдерживаемое окружение и несовместимый релиз отображаются явно.
- Нет вызовов sudo/systemctl/docker, установки без нажатия администратора, публикации релизов или обновления VPS в рамках разработки.

## Capabilities

### New Capabilities
- `runtime-updates`: обнаружение и проверка релиза, независимый от process manager жизненный цикл установки и отката, администраторский интерфейс и сохранность данных.

### Modified Capabilities
- Нет. Исторические release-management/release-automation описывают выпуск пакетов, а не самообновление установленного Go-сервера. Go runtime сохраняет один активный процесс-владелец SQLite.

## Impact

`cmd/codex-lb` (запуск, завершение, блокировка данных), новые narrow update contracts и GitHub/filesystem/process adapters, защищённые admin HTTP routes и Settings/runtime UI. Новые зависимости не требуются. Действующие конфигурация, адрес прослушивания, runtime data и unit/container остаются внешними входами. Для container deployment каталог данных/версий должен быть persistent, writable и разрешать запуск бинарников. Поддержка определяется наличием релизного артефакта для GOOS/GOARCH; текущие артефакты — Linux amd64/arm64.
